📱 Flutter 3.x — vs React Native 0.76
Metric Flutter React Native Notes
App startup (first frame) ~40 ms ~50 ms Flutter is quickest; AOT-compiled Dart, no JS bridge
UI frame rate (60 Hz stress) Stable 60 fps Drops at restarts Flutter's Impeller engine renders directly; no bridge round-trips
Memory (1000-item list, Android) Lower & stable Spikes significantly RN showed major CPU & memory spikes; Flutter scrolled smoothly
Android APK size Smaller AAB/APK Larger (Expo largest) Flutter needs no extra libs like Reanimated
Cross-platform market share (2024) 46% 35% Stack Overflow Developer Survey 2024 / Statista
🌐 Next.js 14 — vs Vite SPA
Metric Next.js (SSR/SSG) Vite SPA Notes
Time to First Byte (TTFB) ~30 ms ~50 ms Next.js serves pre-rendered HTML from server or edge
Time to Interactive (TTI) ~2.1 s ~1.2 s (CSR) Vite wins on client interactivity; Next.js wins on FCP/LCP for SEO
Client JS bundle size ~92 KB ~42 KB Next.js hydration adds overhead; Server Components reduce this
Lighthouse SEO score High (SSR/SSG) Low (blank shell) Vite serves empty HTML until JS loads — crawlers see nothing
Image payload reduction (next/image) 20–50% smaller Manual Automatic resizing, AVIF/WebP, lazy loading built in
🏗️ NestJS 10 — vs Express.js
Metric NestJS (+ Express) Raw Express Notes
Throughput (simple JSON, 1 core) ~15–18K req/s ~15–20K req/s NestJS adds ~10% overhead over Express — negligible in practice
Median response latency Equivalent Equivalent At real-world load with DB queries, difference is immeasurable
Failure onset (concurrent users) ~5–6 VUs ~5 VUs Both fail at similar concurrency; swap to Fastify adapter for +30% RPS
Bug reduction vs untyped Express ~60% fewer Baseline TypeScript + DI reduces production defects (DEV Community study)
Dev onboarding speed 3× faster Baseline Opinionated structure eliminates architecture decision fatigue
🔗 TypeORM 0.3 — vs Prisma
Metric TypeORM Prisma Notes
Read query latency (large dataset) Faster >1,800 rows Faster <1,800 rows Prisma leads on small reads; TypeORM leads as data grows (benchmark by josethz00)
Simple findMany latency delta Within a few ms Within a few ms Prisma official benchmarks: difference too small to affect UX
NestJS decorator alignment Native (@Entity) Schema file (PSL) TypeORM decorators match NestJS patterns — no context switching
Migration workflow CLI-driven, TS CLI-driven, PSL TypeORM migrations are pure TypeScript; no separate schema language
npm weekly downloads (2025) ~1.5M ~3M (Prisma) Prisma has grown to ~2× TypeORM downloads; both production-proven
🐘 PostgreSQL 16 — vs MySQL 8.0
Metric PostgreSQL 16 MySQL 8.0 Notes
Simple OLTP throughput (SysBench) Slightly lower Up to 21% higher peak TPS MySQL edges out on high-concurrency simple inserts (MDPI study, 2024)
Complex analytical queries (TPC-H) Significantly faster Needs manual tuning PostgreSQL's query planner and parallel query far outperform MySQL on JOINs
Point-select throughput (pgbench) Up to 2M QPS Comparable PostgreSQL record: 2M point-select QPS, 137K write TPS (Vonng/pgtpc)
JSONB query support Native + indexed JSON (limited indexing) PostgreSQL JSONB allows GIN indexes; MySQL JSON cannot be indexed the same way
ACID & MVCC concurrency Full MVCC MVCC (InnoDB) Both ACID-compliant; PostgreSQL MVCC has no read-write lock contention
